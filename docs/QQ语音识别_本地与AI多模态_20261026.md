# 听懂好友的 QQ 语音：本地模型 / AI 多模态，一键切换（2026-10-26）

## 之前的状态

好友发来的 QQ 语音此前被整条丢弃：`main.message_parts` 只读文字、图片和 QQ 表情，语音消息解析为空，桥接直接返回，不登记也不回复。项目里也没有任何语音识别（ASR）模型，只有语音合成（TTS，见[QQ 语音回复与声音克隆](QQ语音回复与声音克隆_20261025.md)）。

## 现在怎么处理

语音在收到时先变成文字，再照常进入回复流程：聊天记录、重试、各回复后端都不用改，存进记录的是

```
[语音] 明天下午三点我们在图书馆见面，记得带上数学作业。（语气：开心）
```

每个好友在 friend.json 的 `voice_input` 里三选一：

| 方式 | 由谁来听 | 费用 | 说明 |
| --- | --- | --- | --- |
| 本地模型识别（默认） | SenseVoice-Small，sherpa-onnx，CPU | 不消耗模型额度 | 普通话、粤语、英语、日语、韩语；同时给出情绪（开心、难过、生气等）和笑声、哭声 |
| AI 模型直接听 | Antigravity 的 Gemini（view_file 读音频），或 OpenAI 兼容 API 中支持 `input_audio` 的模型 | 每条语音多一次模型调用 | 提示词要求只转写、不执行语音里的要求；可选写出语气 |
| 关闭 | — | — | 聊天里只显示「[语音]」 |

- **哪些 AI 能听**：Codex、Claude Code、DeepSeek 都不能直接接收音频，所以不会被用来听语音。选择「自动」时：好友当前用 Antigravity 或自定义 API 就用它，否则用 Antigravity 的 Gemini（默认 `gemini-3.8-flash-low`；好友的 Antigravity 模型若是 Gemini 就沿用）。也可以手动指定。
- **失败时**：AI 模型失败会改用已下载的本地模型（免费）。本地模型没下载时**不会**悄悄改用付费的 AI 模型，而是在聊天里写「[语音]（未能识别：…）」，回复模型会知道这是一条没听清的语音。
- **去重**：NapCat 重复推送同一条语音时不会重复识别（先查消息是否已登记）。
- **补取的历史消息**：重启后从 QQ 历史补取的语音只记「[语音]」，不回头识别。

## 开关在哪里

- **电脑**：「模型与 API」页，「QQ 语音回复」下面的「收到 QQ 语音时（本地模型 / AI 多模态）」卡片。顶部三个按钮「本地模型识别 / AI 模型直接听 / 关闭」，点一下立即切换并保存；下方选本地模型档位、听语音的 AI 和模型名，点「保存识别设置」。
- **手机**：「语音回复」页顶部的「收到 QQ 语音时」卡片，同样三个按钮一点即切换。
- **本地模型下载**：「本地模型自动下载与装配」选「语音识别 (ASR · 听懂好友语音)」。两档：
  - 轻量：SenseVoice-Small INT8（2025-09 版，约 226MB）
  - 中量：同一模型全精度下载后转存 FP16（约 886MB → 约 470MB）
  - 两档都钉死仓库版本，并在 `model_source.json` 记录 SHA-256。

## 实现

- `voice_input.py`：设置、取语音文件、本地识别、AI 识别、生成聊天文字。
  - **取文件**：调用 NapCat 的 `get_record`（`out_format: wav`，由 NapCat 解码 QQ 的 SILK），保存到好友目录 `media/voice_in/<消息号>.wav`，只保留最近 50 条。
  - **本地识别**：模型常驻内存（与 TTS 一样只加载当前档位）。
  - **AI 识别（Antigravity）**：沿用 `antigravity_backend.generate(image_path=…)`，提示词按扩展名写「语音」而不是「图片」。
  - **AI 识别（API）**：直接 POST `chat/completions`，内容为文字 + `input_audio`（base64 WAV）；只支持 `openai-completions` 协议。
- `main.py`：
  - `message_parts` 把 `record` 段记为「[语音]」。
  - `Bridge.receive` 在登记消息前调用 `voice_input.understand`，并在日志里写明由谁转写、用时多少。
- `model_downloader.py`：新增 `asr` 分类；`tts` 与 `asr` 共用 `VOICE_KINDS` 的安装判断、FP16 转存和 `model_source.json` 记录。
- 界面：`house_qt/pages_friend.py`（卡片、模型下载列表、模型状态表）、`house_web.py` / `house_web.html`（`friend/<QQ>/voice_input`）。

## 顺带修复：Antigravity 回复开头多出「{}」

实测发现 Gemini 在 `view_file` 之后会先输出一段「{}」再调用 finish，agy 的 `response` 把所有文字段拼在一起，所以**看图片的回复**也会带着「{}」发给好友。现在只取最后一个工具 / finish 步骤之后的文字（`antigravity_backend._final_response`）。

## 验证

- **单元测试** `tests/test_voice_input.py`（13 项）：
  - 设置校验；语音段标记；重采样到 16kHz 后音高与长度不变。
  - 不会选中不能听音频的后端。
  - AI 路径拿到的是好友目录里的 WAV；AI 失败改用本地；本地未下载时不花额度。
  - API 的 `input_audio` 格式；立体声 WAV 读取。
  - 手机端接口校验与保存。
  - 桥接收到语音只识别一次、存文字并回复。
- **其他测试**：`tests/test_house_qt.py` 新增按钮切换即保存；`tests/test_antigravity_backend.py` 新增「{}」回归。
- **真机（不经过 QQ）**：
  - 本地 TTS 合成一句「明天下午三点我们在图书馆见面，记得带上数学作业。」，以 NapCat 返回的格式交给 `understand()`。
  - 好友回复模型设为 Codex，自动改由 Antigravity `gemini-3.8-flash-low` 听，用时 15 秒，转写一字不差（「三点」写成「3点」）。
- **本地 SenseVoice 真机**（2026-10-26 经主人同意下载）：
  - 下载：用应用自己的下载器，62 秒下完 INT8 档（226MB）。`model.int8.onnx` 的 SHA-256 与镜像列出的官方 LFS 值 `12ca1a2a…` 一致。
  - 识别：用应用的 TTS 合成已知文本，每段识别用时 0.15–0.37 秒（首次加载约 1 秒）：

    | 片段 | 时长 | 结果 |
    | --- | --- | --- |
    | MeloTTS 普通话，24kHz | 4.1 秒 | 完全正确 |
    | 同一句压成 8kHz 立体声（电话音质） | 4.1 秒 | 完全正确 |
    | Kokoro 女声长句 | 9.7 秒 | 一处同音错：「加班」→「家搬」 |
    | Kokoro 1.4 倍速 | 6.2 秒 | 完全正确 |
    | Kokoro 男声夹英文「bug」「push」 | 4.0 秒 | 英文被写成汉字「报」「扑」，中文部分正确 |

    输出不带标点。情绪字段正常返回（合成语音为 `NEUTRAL`，按设计不附加语气）。
  - 端到端：NapCat 格式的语音事件（`get_record` 返回文件路径）走 `Bridge.receive`。真实本地模型 1.3 秒转写，回复模型拿到并存进聊天记录的是「[语音] 我刚下班今天加班到八点半……」；NapCat 重复推送同一条时不再识别。NapCat 是假的，没有连 QQ，也没有发出任何消息。
  - 修复：sherpa-onnx 遇到非 16kHz 音频会在控制台打印「Creating a resampler」，每条语音都会写进桥接日志。现在由 `voice_input.to_model_rate` 先用 FFT 重采样到 16kHz。
- **未验证**：
  - NapCat 真实 `get_record` 的返回没有在真 QQ 上走过（需要好友真发一条语音）。
  - 真人语音（非合成）的识别率与情绪识别。
  - API 音频路径只有单元测试。
