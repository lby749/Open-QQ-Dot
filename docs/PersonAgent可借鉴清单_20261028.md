# PersonAgent 可借鉴项与整合清单

调研对象：[wangkant/personagent](https://github.com/wangkant/personagent)（MIT，Python，2026-10-27 查看）。
它不是 QQ 专用框架，而是一个“群聊角色”运行时：自己判断该不该说话，能从纠正中学习，带证据记录、回滚和评测。

## 1. 可以直接借鉴

| 能力 | PersonAgent 的做法 | 对 Open QQ Dot 的价值 | 整合优先级 |
|---|---|---|---|
| 该不该开口 | 被叫到才答；否则由模型判断“真人会不会插话”；连续消息合并成一轮 | 现在主要靠主动频率/冷却，可增加“群聊沉默判断”和“消息 burst 合并” | P1 |
| 多气泡自然表达 | 角色化短句、群聊轻快、连续消息只回一次 | 直接改善“每次只发一句/不自然” | P0（本次已改提示词） |
| 纠正学习 | 同一群两条一致反应、其中一条强，才写入；每次变更可回滚 | 现有记忆可增加“纠正证据 + 变更记录”，避免模型乱改人设 | P2 |
| 证据账本 | 每个学到的称呼/事实有来源、反应、时间和回滚记录 | 和现有回溯中心天然契合，可把“人格变更”纳入回溯 | P2 |
| 每聊天独立记忆 | 每个会话独立 memory | 已有每位好友独立存储；可借鉴“纠正来源”粒度 | P2 |
| 角色与设置分离 | `persona.txt` 与运行设置、平台凭据分开 | 现有 friend.json 已分离；可加强“人格版本”与“原始证据” | P3 |
| 本地优先/隐私 | 所有数据在本地 home；连接真实群前提示告知与同意 | 与本次免责声明一致，可把“告知对方是机器人”做成首次启用检查 | P1 |
| 可评测 | 60 个标注聊天时刻，评“该不该说/像不像角色/纠正是否生效” | 可给 QQ 回复建立离线评测集，避免只凭感觉调提示词 | P2 |
| 连接器分层 | QQ/微信/Telegram/Discord 直连；其他走 AstrBot 等 | Open QQ Dot 已有 NapCat/OneBot；可借鉴“连接器状态/凭据检查”页面 | P2 |

## 2. 不建议直接照搬

- PersonAgent 的浏览器设置页、AstrBot 依赖和跨平台连接器：Open QQ Dot 已有 Qt 桌面端和 DotLink/NapCat，不需要再引入一套 Web UI。
- 自动学习人格：PersonAgent 也要求“两条一致反应 + 强证据”；直接让模型自动改写人设会放大错误，应先做证据和回滚。
- 它的多平台插件生态：会显著增加安装体积和维护面，当前应先做好 QQ 单平台稳定性。

## 3. 建议整合顺序

1. **P0：回复自然度**——多气泡默认、媒体前后允许文字、减少“一句话结束”。
2. **P0：多模态发送**——本地 `media/generated/` 图片/视频 + 真实发送；没有真实文件绝不伪造。
3. **P1：群聊开口判断**——消息 burst 合并；被叫到才答；沉默也可作为正确行为。
4. **P1：首次使用同意**——连接真实群前提示“告知群友这是机器人”，并写入免责声明。
5. **P2：纠正账本**——记录来源消息、反应、变更前后值，接入回溯中心撤销。
6. **P2：评测集**——用真实 QQ 对话构造 50–100 个“该不该说/像不像/纠正是否生效”样例。
7. **P3：连接器状态页**——QQ/NapCat、模型、代理、媒体目录分别显示可用性。

## 4. 和当前项目的对应关系

| Open QQ Dot 现有模块 | 可接入点 |
|---|---|
| `main.py` 回复/主动提示词 | 多气泡默认、媒体前后文字、群聊 burst 合并 |
| `sticker_library.py` / `voice_tts.py` | 媒体发送与表情/语音共用发送队列 |
| `friend.json` / `persona_*` | 人格版本、纠正证据、回滚 |
| `revert_center.py` | 人格/记忆变更纳入统一回溯 |
| `house_qt/pages_friend.py` | 模型来源多选、登录按钮、媒体开关 |
| `tests/` | 新增“该不该说/多气泡/媒体顺序”回归 |

## 5. 结论

最值得先抄的是 **“该不该说 + 多气泡 + 纠正证据”**，而不是它的跨平台外壳。
本次先落地 P0 的提示词与媒体发送；P1/P2 需要单独迭代，不能靠一次改提示词解决。
