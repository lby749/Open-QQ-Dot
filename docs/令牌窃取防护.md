# 令牌窃取防护与威胁模型

## 结论

**完全访问权限 = 当前 Windows 用户的权限。**  
Agent 如果和主程序以同一个 Windows 用户运行，又有命令执行权限，那么它可以通过任意代码、DPAPI、进程内存等方式绕过应用层限制。  
应用层能做到的是“提高门槛、减少明文、阻止常见路径”，不能把同用户完全访问变成真正沙箱。

真正的隔离必须靠 **独立 Windows 账户** 或 **独立虚拟机/容器**。

## 已实现的防护

### 1. 令牌文件不再明文

`house_web.local.json` 里的 `friend_tokens` 在 Windows 上使用 DPAPI 加密：

```text
friend_tokens_protected = base64(DPAPI(json))
```

同时保留 `admin_qqs` 等非秘密字段。  
直接复制文件不能读出 token；但同一 Windows 用户仍可调用 DPAPI 解密，这是已知限制。

### 2. 工具层直接拒绝秘密路径

即使勾选「完全访问」，`validate_path_in_bounds()` 也拒绝：

```text
house_web.local.json
friends.json
friend.json
api-key.bin
api-*-key.bin
.agent_mail_key_v1
.env
credentials
secrets
.ssh/ .aws/ .gnupg/
```

### 3. 命令层阻止明显窃取

`desk_run_command` 和工具注册表的命令执行都会检查命令字符串；包含上述名称/目录时直接拒绝。

这不是完整 shell 沙箱，混淆命令仍可能绕过。

### 4. Funnel 默认关闭

带 `Tailscale-Funnel-Request` 的请求默认全部 403，必须显式：

```powershell
$env:QQ_ALLOW_FUNNEL='1'
```

### 5. 令牌可一键轮换

手机小屋卡片新增「重置访问令牌」：

- 旧二维码/链接立即失效
- 手机需要重新扫码
- 新 token 仍以 DPAPI 加密保存

### 6. 完全访问有明确警告

权限页提示：

> 完全访问等于把当前 Windows 用户权限交给 Agent；即使应用拒绝直接读取令牌，Agent 仍可能通过命令、进程或同用户权限绕过。需要真正隔离时，用独立的低权限 Windows 账户运行 Agent。

## 仍然无法防住的情况

- Agent 以同一 Windows 用户执行任意 Python/PowerShell
- Agent 读取主程序进程内存
- Agent 调用 DPAPI 解密当前用户的数据
- Agent 使用编码/混淆命令绕过关键字检查
- 用户主动把带 `#t=` 的链接发给别人

## 推荐部署

1. 主程序用管理员/所有者账户运行
2. Agent 工具用**另一个低权限 Windows 本地账户**运行
3. 该账户对主程序目录只有读取权，不能读 `house_web.local.json`
4. 不给 Agent `完全访问`，默认只给好友工作区
5. 不需要 Funnel 时保持 `QQ_ALLOW_FUNNEL` 未设置
6. 怀疑泄露时立即点「重置访问令牌」

## 轮换

桌面端手机卡片 →「重置访问令牌」。  
或删除 `house_web.local.json` 中该好友的加密条目，下一次打开手机页会生成新令牌。
