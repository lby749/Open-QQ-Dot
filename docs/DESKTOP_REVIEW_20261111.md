# 电脑端重复实现、检索效率与经验边界审查

本轮以最终发布目录的源码为准，范围是根目录 Python、`house_qt`、`agent_backends`、`dotlink`，共扫描 267 个 Python 文件。手机原生功能由另一条线负责；以下不冒充全项目或全平台验收。

## 已定位并修复

| 问题 | 根因与修改 |
|---|---|
| 普通讨论进入经验库 | 协作房间采用数据任务，消息结构验收通过曾触发通用任务归档。现在聊天模式、房间讨论、邮箱对话不自动成为任务经验或工作流；未经本次客观验收的完成声明留在任务历史。明确的用户纠正和偏好继续按原有来源保存。 |
| 检索随历史数量变慢 | 每次经验检索都构造写入型经验库并扫描全库高置信记录。读取路径取消全库清理，仍逐条校验返回记录签名；写入路径保留历史清理。查询只读所需文字字段，不再加载向量字段。 |
| 当前好友记录被挤出 | 全局共享候选先占据 400 条截断，再做签名和好友筛选。现在先排除未验证的外部共享候选，并优先当前好友；伪造共享签名不能晋升为可靠经验。 |
| 一条坏数据阻断全部参考 | 非对象或损坏的经验元数据可能中断整轮读取。现在逐条跳过异常记录，保留其他合法参考。 |
| ACP/OpenCode 两套实现漂移 | 旧门面和实际后端各保留一份传输实现，测试可能只覆盖旧代码。删除 417 行重复实现，旧导入入口延迟指向实际生产类；覆盖三种导入顺序避免循环导入。 |
| 汇总重复任务与旧轮次 | 汇总曾将原始任务、最近 40 条群聊和旧主持汇总一起发送。现在有明确本轮任务时只取该轮成员返回，限制输入长度；程序派发的配置与服务商内部身份分开表述。 |
| 运行时打包过滤不足 | 可选运行时打包分支曾只排除少数日志目录。现在构建和安装共用过滤，排除数据库、会话、配置和令牌；本轮安装器默认仍不捆绑 NapCat。源码包包含蓝色版 android/，排除废案 mobile/、Gradle 缓存与签名材料。 |
| 已有解释器仍触发下载 | 安装器只枚举 3.11–3.12，漏掉程序已支持的 3.13。现支持 3.11–3.13，并在采用前实际导入 SQLite/ctypes/SSL、检查64位。未找到健康本机环境时仍使用私有 Python 下载路径。 |

AST 精确匹配得到的较长重复候选从 21 组降到 2 组。保留的简单构造及界面切换逻辑没有为了减少数字而再引入抽象。静态完全匹配不能发现所有语义重复。

## 同一数据集的性能对照

合成 50,000 条记录、100 个身份、每轮读取同一好友最新 400 条；预热后测 5 次，包含 Python 分配跟踪。记录由测试脚本直接构造，**不是 50,000 次真实任务的验收证据**。

| 指标 | 修改前 | 修改后 |
|---|---:|---:|
| 中位耗时 | 628.877 ms | 37.399 ms |
| Python 峰值分配 | 32,393,098 B | 935,278 B |
| 返回记录 | 400 | 400，ID 与顺序相同 |
| 返回记录签名校验 | 保留 | 保留 |

本基准约快 16.82 倍；不代表模型推理延迟、真实任务成功率或整个程序内存降低同一比例。

## 实际验证与不足

- 真实 Luna：失败反思、修正代码、独立 Python 行为测试、相似任务召回，3 次调用共 32.716 秒。测试覆盖空列表、单元素、负数和零；其他好友未召回到该经验。
- 指定 QQ 好友：按现有人设使用 Luna 生成一次进度消息，真实发送一条，回执与历史匹配；未改好友配置、未重置 QQ 登录。
- 蓝色手机协作：3 次真实 Codex 调用完成主智能体分工、成员返回和汇总；讨论保留在房间历史，经验表及经验审计表均未自动增加。汇总第一次未正确报告配置，未计为全通过；修复本轮上下文后另做一次汇总复验，未重跑工作成员，正确引用了 gpt-6-luna/low 和算术结论。
- 本机 OpenCode 服务元数据读取未连通；合并后的 OpenCode/ACP 协议通过本地真实 HTTP/stdio 组件测试，但本轮没有该服务的真实模型生成证明。
- 未调用 Claude。没有连续多日、任意失败自动修复、所有模型档位、所有跨系统安装的证明。

本轮定向及集成回归报告分别保留，不把重叠运行相加当成独立功能数。协议测试基线存在两个 Windows 下的替身程序定位失败；已把替身改为由当前 Python 显式执行。合并传输后另有一处旧模块 mock 位置需要迁到真正传输类；失败日志和修复后的结果均保留。不能把替身执行成功当成 Cursor/Qwen 账号已验收。

最终同进程合并回归为 **160 passed / 46.54秒**，覆盖本轮相关任务、反思、检索、权限、传输、设置、网页与打包代码。它不是全项目的全平台全量测试。

安装器先在空应用目录实际执行私有 Python 下载及依赖安装，SQLite/SSL/Qt/机器人基础模块校验通过，安装后 EXE `--prepare-only` 返回0；另一空目录实际复用系统 Python3.13并通过同样检查。后续升级是否保留合成用户数据、是否重复下载和最终文件哈希另列在交付目录的测试结果中。本机有开发环境，这不能替代干净 Windows 云机验收。

完整源码包含上游公开隐私对抗语料 `android/privacy-benchmark/src/main/resources/corpus_c.jsonl`。其 LF 归一化哈希 `8276f1de054daceef0d9e78fca81fea7e0ebed6bac5ac7e034684377077e6945` 已与[固定上游提交](https://github.com/danielealbano/android-remote-control-mcp/blob/16f39717ce0969aa81a4ec132ba1cad861ba46cc/privacy-benchmark/src/main/resources/corpus_c.jsonl)逐字节核对；其中的凭据样例不是用户账号资料。扫描仅对这一路径和精确内容允许，改动后仍阻断，其他凭据模式继续检查。此测试模块不进入 APK。
