# 可学习工作流、长期执行、跨智能体协作与 QQ 附件

本轮继续使用当前 `Open-QQ-Dot` 源码、现有任务数据库、后台队列、独立验收器和智能体邮箱。保留用户最近的修改和原有桌面组件。

## 从任务和纠正中学习

入口：**任务中心 → 可学习工作流**。

- 已通过真实独立验收的单独任务会沉淀为流程草稿；已人工验收的任务也可学习。已有长期目标可在“全部任务”选中最终验收后的记录，点击“学习为工作流”。
- 流程包含授权范围、阶段说明、目标文件/测试命令/数据字段/网页验收文字、项目目录、每轮调用与词元预算。不复制登录凭据、权限或任意命令行配置。
- 可直接编辑阶段、指定执行智能体、填写纠正意见并保存版本。纠正会带入该版本之后创建的执行阶段，而不是只作为日志保存。
- 保存新版本不会修改正在运行的旧版本。实际修改会关闭未来的定时执行，须重新开启；没有改动时刷新或执行一次不会制造新版本、关闭原定时安排。
- 学习草稿默认不执行，不自动开启定时。同一来源任务再次学习不会覆盖用户已做的纠正；工作流自身的输出不循环生成“新经验”。

## 长期与周期执行

在同一个页面设置本机时间、间隔、剩余轮数和预算，再开启定时。

- 每轮仍是现有 TaskManager 的一个持久化长期目标，阶段顺序执行，经过独立验收后交接。
- 调度与创建目标在同一 SQLite 事务中落盘。重复检查和并发调度不会重复创建同一轮；上一轮正在执行、暂停或等人处理时不重叠运行。
- 程序重启保留状态；错过多个周期时只补一轮，不集中补发。电脑和后台服务需要运行，关机期间无法执行。
- 失败、权限不足、额度或资源受阻时保留检查点，不靠无限重试消耗额度。修改流程不会增加已经开始的那一轮的权限或预算。
- “停止后续定时执行”只停止后续轮次，当前目标在“全部任务”中暂停、继续或终止。
- 可勾选“全部阶段客观验收通过后自动完成整轮”。此模式明确以每个阶段的客观验收作为整轮标准，允许无人持续运行；研究、通用任务等仍需人工审查的阶段不会自动确认。
- 自动完成还要求真实 TaskVerifier 回执。调用者提交的 `success=true` 或伪造的验收标志不能触发自动确认；重启后也不能将这种声明当成真实验收。

手机端“全部 → 可学习工作流”可查看、执行一次、停止后续轮次，并打开相同任务的审批与结果。阶段编辑和录制入口目前在桌面。

## 跨智能体交接

每个阶段可选择当前好友已启用的 Codex、Claude、Antigravity 或已配置外部引擎，也可沿用当前协作编排。执行时再次检查引擎与权限，流程不能启用原来未授权的引擎。

前序阶段只有验收通过后，结果与产物引用才进入后续阶段。现有智能体邮箱保存同一流程的派发、结果、验证状态与线程；未验证结果不标记为已验证。没有另建一套智能体通信引擎。

真实模型测试已完成 **Codex `gpt-6-luna` → Antigravity `gemini-3.8-flash-low`**：Codex 写入 `inventory.json`；Antigravity 读取该文件并编写核验脚本；TaskVerifier 真实执行脚本通过，两个阶段全部验收后进入总体验收。测试没有向 QQ 发送汇报，没有调用 Claude。

首次测试将每阶段限为三次模型调用，第二阶段在写出脚本后触及上限而正确暂停；记录单独保留。将受控测试每阶段预算设为六次后重新验证成功。此结果既验证真实跨引擎交接，也证明调用上限不会被偷偷扩大。

## 鼠标键盘示教：当前支持浏览器

桌面工作流页有“浏览器鼠标键盘示教”：输入网页地址并开始，程序打开独立浏览器；完成操作后回到桌面停止，并学习为流程草稿。

- 录制网页中的点击、文字填写、下拉选择与滚动，使用网页元素定位，不监听其他应用的键盘。
- 密码、令牌等敏感输入会中止录制，不把相应字段值写入步骤；此版本不支持表单回车提交，请用鼠标点击按钮。最多 20 步、10 分钟。
- 步骤能在阶段表格中修改，回放复用已有真实浏览器执行器，不调用模型。保存真实截图，按配置验收，遇到登录、支付或发布等限制时停止。
- 好友切换不能把录制保存到另一好友；停止或出错不会悄悄继续录制。
- 浏览器档案和录制文件保存在该好友的 `media/demonstrations`，不混入项目代码，也不成为文件任务撤销的目标。

已在受控本地页面，用真实浏览器事件录制填写和点击，再由任务 Worker 在不自动操作的页面真实回放，生成 PNG 并通过验收；没有模型调用。

**系统全桌面的鼠标键盘录制仍未实现**。跨域嵌入页面、复杂快捷键和各种网站的变化也没有完整覆盖，不能把当前浏览器示教说成全平台、任意应用的通用录制。

## QQ 文件、图片、视频

- 手动发送：主页切到 **QQ 实时消息**，点击输入框下方“＋”，选择文件。自动按后缀识别文件、图片和视频；普通工作台的“＋”仍用于引用项目文件。
- 智能体发送：新增 `qq_send_attachment` 工具，Codex/Claude 的 MCP 和现有函数工具调用路径共用。只允许当前任务项目中的文件，接收者固定为当前绑定好友；对外发送沿用独立的消息审批。
- 发送前核验当前 QQ 登录账号与好友绑定账号一致；有实际消息回执才记为发送成功。
- 发送标识、文件摘要和回执落盘。超时、进程中断或回执不明时不自动重发；明确尚未尝试发送的连接/账号错误可在修正后安全重试。本地聊天记录失败不会导致重复发送。
- 三类附件已分别向用户原先授权的测试好友实发一次，全部取得回执，`get_msg` 回读分别为 `file`、`image`、`video`。测试素材为单独生成的小文件、测试图和两秒视频，未发送私人资料。

采用 NapCat 官方支持的[文件、图片、视频消息段](https://napneko.github.io/develop/msg)，与[当前 OneBot 接口](https://napneko.github.io/onebot/api)保持一致。

## 语音通话

现有 QQ 语音消息与本地语音合成继续保留。检查 [NapCat 当前接口文档](https://napneko.github.io/onebot/api)和[上游动作路由](https://github.com/NapNeko/NapCatQQ/blob/main/packages/napcat-onebot/action/router.ts)，没有找到当前项目可使用的通话发起和实时音频通道。

**本轮没有实现 QQ 实时语音通话，也没有用发送语音消息冒充通话。** 若后续接入实际通话方案，还需要验证呼叫、接听、挂断、实时收听与语音输出的完整链路。
