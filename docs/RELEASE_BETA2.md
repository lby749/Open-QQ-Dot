# 1.0.0-beta.2：本轮修改与证据

日期：2026-11-11。基于桌面「openqqdots-最终发布」源码。电脑端、机器人接入与群聊调查由主智能体完成；子智能体只负责蓝色 Android 客户端。未使用 Claude，未重置 QQ 登录或机器人密钥。

## 桌面界面

- 两种 QQ 连接方式由下拉框改为横向分段切换；切换只显示对应面板，保留另一条连接。
- 所有共用的顶部切换条增加宽度与上下留白；发生横向溢出时为滚动条保留高度。
- 修复窄窗口顶部连接状态被挤压：1050 宽时原先约298像素文字只有133像素空间；现在好友信息与连接操作在宽度不足时换行。
- 19项相关 Qt 检查通过；150% 缩放下13项相关检查通过，两组有重复项目，不能相加当作独立功能数量。
- 用重新构建的 beta.2 EXE 实际打开控制台和两种连接面板，观察到了新的分段组件。切换前后现有 QQ、桥接与运行时进程保留，好友配置和加密密钥文件哈希未变。
- 原生窗口工具对 pythonw 的应用标识绑定失败；最终通过正式 EXE 启动的 python 进程完成真实界面检查。没有改用 Windows MCP。

## 官方机器人与群聊

五个独立 AppID 已完成真实访问令牌鉴权、身份查询与网关连接；保存的是本机加密密钥。重新打开桌面和切换连接面板之后，五行仍显示已连接官方服务。

自动加入指定三人群**尚未完成**。个人 QQ 管理接口当前读不到可用管理凭据，CSRF读取返回客户端密钥错误；已安装 NapCat 只找到机器人入群选项设置，没有核实到真正邀请动作。官方公开页面提供的是手机 QQ 机器人卡片入口，不能用“已生成链接”替代实际入群。

没有取得该群的各机器人事件与回复授权，没有向群里伪造协作演示，也没有用普通群号代填官方群 OpenID。网关在线不能算群内收发、分工或汇总闭环通过。

## 示例与检索

1080个手动组合各有独立生成的24条交替消息，共25,920条，转换为每组12个回复示例，共12,960个。提示词与五个手动条件精确对应；没有让大模型生成主题标签，也不把这些合成示例或全部聊天写入任务经验库。

检索索引改为最后一条上下文加当前发言，避免更早的上下文在后续条目中反复出现而污染当前条目的身份。完整先前对话只用于表达示范。低、中、高占用选择实际对应的嵌入与重排模型；显式自定义检索配置优先；权重共用，好友和模型签名约束缓存。四个缺失模型已下载，已有大模型权重复用。

40项最终相关检查及7个子断言通过。真实权重对比没有复用旧大模型标签：

| 数据与目标 | 单向量首位 / 前五 | 完整组合首位 / 前五 |
|---|---|---|
| 两个旧说话人库，48个已知条目查询 | 72.92% / 83.33% | 95.83% / 100% |
| 低占用，15条固定人工改写 | 93.33% / 100% | 100% / 100% |
| 中占用，同15条改写 | 100% / 100% | **86.67% / 100%** |
| 高占用，同15条改写 | 100% / 100% | 100% / 100% |

中占用首位排序回退保留为未解决项；不能只报告改善结果或针对这15条样本调参。旧库测试是已知条目恢复，固定改写也是小样本，均不能当成开放域准确率或真实任务成功率。

旧库48查询完整过程约19.81秒，融合排序中位约7.68毫秒；进程末端内存约3341MB、CUDA分配峰值约2229MB。新组合低/中/高占用45查询过程分别约10.05/5.17/9.59秒，CUDA峰值约288/759/2191MB；模型加载、批处理及缓存不同，不能据此宣称中占用在所有机器都最快。末端内存和峰值也不是连续运行资源曲线。

去重检查未发现整段重复对话；长句重复和标识符检查通过。私有原文的20字符重叠检查只核实了一份已定位来源，不能写成用户提到的两份早期原始记录均已完成逐一核对。1080组预览切换通过不代表全部对话完成人工质量审查。

## 真实模型与 QQ

保留一条真实失败：一次 Luna 生成后确实发到授权 QQ 并在历史中核对了消息回执，但完整复用了例句，且带入示例背景物品信息。传输通过，回复质量未通过。

另用新场景分别关闭/开启示例做了两次真实 Luna 调用，耗时8.62/12.91秒。两次均遵守袖口湿、包和纸袋未湿、人未烫伤的本轮事实；此项没有再发 QQ 消息。有限复核不能消除上一条失败或证明所有模型均不照抄。

## 蓝色 Android 及服务权限

蓝色正式客户端已构建 beta.2（版本码4），并在现有模拟器覆盖安装，保留配对与既有权限。手机子任务的22项原生测试通过，最终 GMS APK 与模拟器安装包哈希一致。诊断界面显示中文摘要，可展开原始技术细节。

服务端补齐好友令牌的任务、审批、通知和研究归属检查；无owner绑定的旧健康概览拒绝普通设备，保留显式管理员接口。79项受限 HTTP/SQLite 专项及额外1项研究 owner/project 对抗检查通过，不能外推为所有旧路由或实体手机权限都已验收。

## 发行与未验收项目

发行仍标为 BETA。源码、绿色应用包、Windows一键配置安装器和两个蓝色 APK 分开提供。私人数据、密钥、会话、数据库、模型权重和本机依赖不随源码包发布。薄启动EXE必须与配套源码和资源一起使用；首次安装需联网准备缺失依赖，复用可用环境和下载缓存。

最终逐文件核对发现：旧的全层级 `data/` 过滤误删了 Android 包名中的66个 Kotlin 源文件，初次源码压缩包因此不完整。现已将私人数据规则限定到项目根目录，同步修正 Git 忽略和归档核查语义；10项相关检查通过。最终源码包另外逐项对照 APK 构建时的源文件哈希，保留正式 Android 源码，排除缓存和子模块本机路径文件。

最终包的一致性、哈希与本机隔离安装结果见发行目录的核对记录。新隔离目录中的深层依赖导入、Qt组件、1080组资源与启动器检查通过，覆盖安装保留合成用户数据且未报告重复下载。已有 Python 的主机上建立新目录，不等于无 Python 的干净云 Windows；本轮没有此类云机证明。

自动入群、官方群多机器人真实协作、中占用检索首位回退、回复照抄的普遍解决、Zcode/反重力所有模型组合、实体手机、双工通话、多日无人值守、macOS/Linux原生发行和干净云端全量仍有未通过或未验证项。本轮未重新运行全部项目测试，因此不将专项数量换算为“85分工程＋15分真实环境”的新总评分，也不标记全功能完成。
