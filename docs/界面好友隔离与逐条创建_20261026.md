# 界面好友隔离、切换好友刷新与逐条创建（2026-10-26 续作）

Codex 在 12:14:24 被用量上限中断（`usage_limit_exceeded`）。中断前它刚跑完中文化轮次
（`../audit-20261026-language/targeted-language-final.xml`，12:09:02，116 项全过，0 失败）。
之后队列里的 5 条要求一条都没有被执行，每条都立刻再次撞上限报错。本轮接着做这 5 条里已经明确的部分。

## 1. 协作网络不再读全库

截图里的「智能体协作网络」显示的是别的任务留下的协作记录：`house_qt/collaboration.py` 调
`collaboration_view.snapshot(...)` 时没有传 `owner`，而该函数支持按好友过滤。

- 现在按当前好友取数，标题下方写明「当前好友 <qq>」。
- 没有选中好友时不再退回全库显示，改为空状态提示。
- 好友切换后页面会重新取数（`loaded_for` 记录当前好友）。

## 2. 运行计数按好友过滤

`ui_dashboard_data.system_snapshot` 之前没有 owner 参数，而「任务状态」「系统概况」「你的工作台」
都在好友页面里，却把所有人的任务、审批、智能体、邮件一起算进去。

- 新增 `owner` 参数：任务、审批、智能体、收件箱计数与明细都按 `owner_id` 过滤；
  邮件按收件智能体所属好友过滤（邮件行本身没有 owner）。
- 不传 owner 时行为不变（全库），供后续管理视图使用。
- `house_qt/workspaces.py` 的计数页改传当前好友；「Token 与缓存」改传 `usage_snapshot(…, qq)`，
  该函数本来就支持按好友统计。
- 计数页底部标注「当前好友 <qq>」，避免再次误解成全系统数据。

## 3. 切换好友后按新好友刷新

原来 `show_friend(qq, page='homePage')` 每次都把界面弹回智能体控制台。现在：

- 不指定页面时留在当前页，只重画；指定页面时保持原有跳转语义。
- 新增 `mark_all_stale()` / `refresh_for_friend()`：所有好友相关页面（包括只通过工作区才能到达的
  协作网络、运行计数页）都会在切换后按新好友重新取数。
- 页头标题与 QQ 号随当前页重新计算。

`tests/test_house_qt.py::test_console_is_default_home_and_overview_remains_accessible` 里断言
「切好友回控制台」的那两条，已按新需求改为「留在好友总览并按新好友刷新」，并在测试里注明原因。

## 4. 自主规划 / 自主研究 / 浏览器自动化：按条创建

截图中的问题是一个巨大的空文本框，最后一个按钮——一次只能建一个任务，信息也没有结构。

- 改为清单式：输入一行 → 回车或「添加一条」进入列表；列表可多选删除、可全部清空。
- 每一条单独创建一个任务（不等同合并），按钮文字实时显示「创建 N 条」；某一条失败不影响其余，
  结果提示里给出成功条数与第一条失败原因。
- 目标模式保留授权范围、验收标准、自动开始；浏览器模式每条是一个网址，逐条校验 HTTP/HTTPS。
- 创建区统一用面板同一套 Fluent 按钮（PrimaryPushButton / PushButton），清单列表用与卡片一致的边框与圆角；
  数字输入框只改外框，保留系统原生上下箭头——实测覆盖箭头子控件会把箭头画到圆角框外，反而更不齐。
- 布局预览（无头渲染，字体已加载）：`build/autonomy-goal.png`、`build/autonomy-research.png`。

## 5. 模型共用（核实 + 说明）

代码层面模型本来就是共用的：`model_downloader.MODEL_CATALOG` 的所有 `target_dir` 都在
`<项目根>/data/…` 或 `build/…` 下，`project_root()` 只受 `QQ_BRIDGE_HOME` 影响，没有按好友分目录。
误解来自界面：下载卡片在好友页面里，看起来像每个好友各存一份。

- 在「本地模型自动下载与装配」卡片里写明：模型只保存一份、所有好友共用，只有「生效模型选择」按好友保存。
- 新增回归断言：模型目录不含 `friends`，`project_root()` 与 `house_settings.root()` 一致。

## 6. 堆得太多：长页面可折叠

好友的模型页一屏塞了 16 张卡片，找一样东西要滚很久。`Card` 现在支持折叠（`collapsible` /
`collapsed`）：折叠后只留标题栏和「展开」按钮，展开/收起状态互不影响功能；折叠时标题栏上的保存按钮一并隐藏，
避免出现「能看到按钮但看不到它在改什么」。

模型页的默认状态：模型来源、Codex/Claude/Antigravity、工具服务、本地模型下载装配、生效模型选择保持展开；
上下文、本地模型兜底、程序降级、语音回复、语音识别、电脑工作台、话题知识库、模型用量 默认折叠。
整页高度由 16 个展开段落改为 5 个展开 + 6 个单行段落。

预览：`build/model-page-folded.png`（整页，1241×2663）。
