# 与 ChatGPT Dot / Work 的功能对照

本项目的目标是用自己的本地电脑执行 QQ 助手任务。模型推理可以使用已配置的云端服务；不部署云电脑，不要求关机后持续运行。这里对照的是公开的 Dot/Work 功能说明，没有把 Muse 当作另一个已核实的公开产品协议。

| 能力 | Open QQ Dot 当前状态 | 进一步实现的条件 |
|---|---|---|
| QQ 作为入口，多好友独立上下文 | 已有，保留 | 当前以私聊为主 |
| 长期记忆、偏好、人设、主动联系 | 已有，保留；无本地模型有程序降级 | 规则分类不等于完整语义分析 |
| 多模型、工具调用、HTTP 功能接口 | 已有多 CLI 和 API；新增通用功能API | 每个服务需要操作者自己的账号/密钥 |
| 本地文件与程序任务 | 已加入按好友授权的工作目录与命令入口 | 命令权限须单独开启，最长90秒 |
| 网页研究和本机打开网页 | CLI 联网和打开 URL 已有 | 打开 URL 不是浏览器 DOM 自动化 |
| 已登录浏览器的多步自动操作 | 未实现统一适配 | 可接本机浏览器自动化/MCP，需要单独管理会话和权限 |
| 桌面截图、应用点击和视觉控制 | 未实现统一控制器 | 需要本机 UI 自动化和可控的权限/操作记录 |
| 通用长任务排队、暂停恢复、边聊边执行 | 只有现有的资料/人格专用任务系统 | 需增加通用持久任务队列；当前不宣称具备完整 Dot 调度 |
| 多代理并行、任务间协调 | 本版本没有通用编排 | 可基于隔离工作目录与 CLI 会话另建任务执行器 |
| 电脑关闭后运行 | 按本项目目标不提供 | 本机运行需要电脑和程序在线 |

从工程上，本地电脑能够提供计算、文件和软件环境；仅更换模型来源不会自动得到浏览器自动化、桌面控制和长任务调度。当前版本先完成统一工具入口与权限边界，保留原有聊天和管理界面。

官方依据：[Dot 的电脑与应用连接](https://learn.chatgpt.com/docs/dots/computers-and-apps)、[Dot 的任务与记忆](https://learn.chatgpt.com/docs/dots/tasks-and-memory)、[ChatGPT Work](https://learn.chatgpt.com/docs/get-started-with-work)。官方 Dot 的托管环境和插件授权属于其产品，不随本项目复制。
