# 本地模型：CUDA / MPS / Metal / CPU

## 设备规则

| 推理路径 | auto 的严格优先级 | 检测依据 |
|---|---|---|
| PyTorch：BGE-M3、BGE重排、自定义encoder / cross-encoder | CUDA → MPS → CPU | `torch.cuda.is_available()`、`torch.backends.mps.is_available()` |
| llama.cpp：GGUF分类、对话共用服务、数据集标注 | CUDA → Metal → CPU | 所选原生 `llama-server --list-devices` 的输出 |

PyTorch 的 MPS 不用来判断 llama.cpp 是否支持 Metal。没有可用 GPU 时才选择 CPU；模型已因后端故障降级时复用该次缓存，不会每条消息反复尝试占满显存。卸载或闲置后重载会重新按优先级检测。

手动选择 `cuda`、`mps` 或 `cpu` 时，不会悄悄换成其他设备。GGUF 也接受 `metal` 作为 `mps` 的别名，实际运行状态记为 `metal`。

## 配置

全局选项在运行目录 `house.local.json`，合并字段即可，不要覆盖原有配置：

```json
{
  "local_models_enabled": true,
  "inference_device": "auto",
  "local_model_devices": {
    "embedding": "auto",
    "rerank": "auto",
    "classifier": "auto"
  }
}
```

优先级：模型自身明确的 `device` → `local_model_devices` 对应组件 → `inference_device` → `auto`。组件名还包括 `custom_embedding` 和 `custom_rerank`。好友的本地检索模型配置仍使用已有 `retrieval_api.embedding.device` / `retrieval_api.rerank.device` 字段。已有的 `cpu` 配置保持手动CPU，不被自动改成GPU。

GGUF 使用已有 `build/message-classifier-runtime/runtime.json` 的 `device`，支持可选 `cpu_server` 和 `metal_server`；未指定时可使用同一个包含相应后端的原生二进制。旧清单中的 `CUDA preferred; ...` 描述兼容为auto。模型路径仍为ASCII相对路径，以兼容原Windows运行包。

Windows的新清单默认程序名为 `llama-server.exe`，macOS / Linux为 `llama-server`。使用者须提供当前平台、架构兼容的二进制；下载模型权重不会同时安装原生推理程序。路径也可以显式指向已安装的程序，例如macOS的 `/opt/homebrew/bin/llama-server`。

桌面硬件下拉框已提供auto / CUDA / MPS / CPU，保持原组件和布局。应用选择时保留已有原生程序路径、上下文、slots、Flash Attention、KV量化和其他启动参数。已经载入的服务或模型需要卸载或重启后应用新的设备设置。

标注CLI保留旧 `--cpu`，另支持：

```text
python dataset_annotation/cli.py run ... --device auto
python dataset_annotation/cli.py run ... --device mps
```

## 精度、缓存与资源

- CUDA继续使用原FP16、批大小和推理路径。BGE-M3与BGE重排继续直接在目标GPU上以FP16创建模型，并沿用原权重拷入方式，没有新增常态CPU往返传输。
- MPS优先使用FP16；CPU使用FP32，避免CPU半精度算子不支持或效率低的问题。磁盘上现有FP16权重可以加载进CPU的FP32模型，不需要重下或永久转换为FP32。
- BGE-M3的4条批处理、BGE重排的16条批处理、自定义模型的8条批处理不变；池化、归一化、重排输出接口不变。保留原向量版本标识和缓存结构；实际运行精度以设备状态为准，跨精度结果可能存在舍入差异。
- 保留常驻预加载入口和BGE闲置卸载；CUDA释放CUDA缓存，MPS释放MPS缓存，CPU不调用GPU缓存接口。自定义模型换模型时释放旧模型，并提供 `small_models.unload()`，不另建模型管理器。
- 仅遇到明确的设备、显存或后端算子兼容错误才自动降级。失败模型与其引用先释放，再清理相应设备缓存；GGUF先停止所属服务，再启动下一后端。回退日志记录来源、原因和目标设备。
- 文件缺失、损坏、哈希不匹配、维度/权重形状不匹配、错误配置和普通程序错误不触发设备回退。HTTP请求慢或超时也不被当成CUDA故障自动转CPU。
- 手动模式推理OOM会释放失败的所属资源并报错，不转用CPU。共享GGUF服务若失败，由拥有者重启，客户端不会额外启动一个重复大模型挤占内存。

CPU计算可能需要比FP16 GPU更多内存。多个模型同时运行时仍需为模型权重、上下文、KV缓存和其他应用留空间。保留用户原有上下文和量化设置，不通过偷偷减小参数或强制CPU来规避显存压力。

## 依赖安装

- 通用 / macOS MPS：`python -m pip install -r requirements-embedding.txt`。
- 保持原NVIDIA CUDA 12.8构建：`python -m pip install -r requirements-embedding-cuda.txt`。
- Windows / Linux x64明确选择CPU轮子：`python -m pip install -r requirements-embedding-cpu.txt`。
- 已经有正常工作的CUDA PyTorch时不必重装；通用文件不再强制带 `+cu128`，也不会因普通安装而强行把满足版本要求的现有CUDA包换成CPU包。

`requirements-local-models.txt` 仍是可选依赖，不会下载模型权重。GGUF使用原生llama.cpp，不能用安装PyTorch MPS替代Metal版二进制。本次不要求MLX转换，也没有加入MLX运行时。

## 修改文件

核心选择规则：`inference_device.py`。实际接入：`embedding_provider.py`、`reranker.py`、`small_models.py`、`message_classifier.py`、`dataset_annotation/annotate_client.py`。安装与配置：`model_downloader.py`、两处Qt设备选择、标注CLI、依赖清单及示例配置。其他调用本地模型的入口继续复用这些服务。

本轮没有继续修改QQ通信、Agent调度、记忆或Web API逻辑。工程中那些模块此前第三轮修复的改动仍保留。

## 验证与边界

本轮实机为Windows、RTX5070、PyTorch 2.7.1+cu128：

- CPU：真实BGE-M3权重以FP32完成1024维向量推理，批2、测试进程4线程，加载约3.59秒、样例推理约0.070秒，结果有限且L2范数约1。微型随机本地XLM-R / BERT另验证Embedding、重排与闲置卸载再加载；未下载模型。
- CPU原生GGUF：已有Qwen3.5-9B-Q4_K_M完成分类，load_count=1；4096上下文、1个slot，加载约4.37秒，分类约28.43秒。
- CUDA BGE-M3：原实现和新实现在同一常驻模型上交错各100轮，批4、67 tokens，FP16保持不变，向量最大绝对差为0。中位延迟7.734 → 7.759 ms，差约+0.32%；配对bootstrap中位比值95%区间约0.982–1.028。未观察到超出本次测量波动的差异，不能把这一小样本当作所有负载零性能变化的保证。
- 原生GGUF auto：实际选择CUDA；保留已有Flash Attention与q8 KV参数时，样例分类约6.51秒，load_count=1。额外省略这些原有调优参数的试验首次请求30秒超时，已如实保留失败记录，未据此自动转CPU。生产代码保留原参数。
- CUDA OOM、MPS不可用、MPS算子不支持、Metal检测及强制设备行为使用模拟测试；没有故意耗尽真实显存。
- 未在Apple硬件或Linux机器实测，不宣称MPS/Metal性能、所有推荐模型或Linux CUDA已经实机验证。新增CI矩阵尚需推送到GitHub后运行。

这次改造只覆盖本地推理链路，不表示原有Windows QQ启动器和全部桌面功能已经整体移植到macOS / Linux。完整验证记录见 [本地推理验证结果](本地推理验证结果.md)。

上游API依据：[PyTorch MPS](https://docs.pytorch.org/docs/stable/notes/mps.html)、[llama.cpp server参数](https://github.com/ggml-org/llama.cpp/blob/master/tools/server/README.md)。
