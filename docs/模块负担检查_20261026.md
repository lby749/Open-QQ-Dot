# 模块与工具负担检查（2026-10-26）

## 结论

存在上下文过多、工具相似、指令矛盾和资源争用导致实际表现变差的风险。当前项目的文件数量没有直接等同于每次模型看到的模块数量，本轮未发现“当前完整工具集比极简工具集更差”的证据。样本不足以排除大量工具、复杂任务和长期运行下的退化。

参考 Anthropic 的[上下文工程说明](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)和[大规模工具使用说明](https://www.anthropic.com/research/advanced-tool-use)：应控制实际上下文、保持工具清晰，并在工具规模扩大时按需检索；不能用“已经装了很多模块”直接推断模型变笨，也不能承诺工具越少越好。

## 当前实际输入

- 当前好友普通入口的项目工具为 **9 个，定义 2379 字符**；工作任务过滤后为 **2 个**。不包含提供商内置工具，也不包含未启用的外部 MCP。
- 当前没有已配置功能 API，外部 MCP 未开启，手机未配对，本地聊天模型兜底未开启。没有因此悄悄切换到较弱本地模型的证据。
- 程序内部工具注册表有 12 项，不代表 12 项全部进入每个模型请求。未选中的模型后端、全部语音/向量模型权重和所有 Python 模块也不会整包进入 LLM 提示词。
- 正式好友最近保留的 4 次生成记录，完整文本为 2734–2929 字符；没有错误记录。记录很少，不能代表长期运行。
- 代码已有按工作任务排除手机/聊天工具、检索分组预算、历史窗口预算和相同上下文去重。检索预算不覆盖所有工具定义；启用大量自定义 API/MCP 后仍有扩张风险。

## 本轮实际修复

1. **只读模式工具误展示**：原先只读仍列出写文件和运行命令，调用后又拒绝。现在只提供实际可用的文件工具，兼容旧 `read_only=true` 配置，命令说明与界面也反映有效只读状态。
2. **Claude 指令冲突**：原先基础规则一概禁止修改文件，同时又要求通过 MCP 写入项目。现在统一为“仅通过已开放工具按现有权限执行明确任务”。命令、路径、只读和审批门禁没有放开；移除了此处条件不可能成立的提示词分支。

这些问题会制造不必要的工具失败或拒绝任务，不能简单归因于模型本身能力下降。

## 真实模型对照

使用隔离好友、受控 CSV、真实文件工具，无 QQ 发送。两类任务为读取计算、读取后写 JSON；当前完整普通会话工具集为 12–13 项，极简对照只提供 1–2 项。正式 TaskManager 工作入口还会进一步排除聊天与手机工具，本表不是完整多轮任务闭环的完成率。

各条件使用同结构、不同数值的四行 CSV，这是工程小样本对照，不是严格相同输入的因果实验；没有重复测量或统计显著性结论。

| 模型 | 极简工具集 | 当前完整工具集 |
| --- | ---: | ---: |
| Codex gpt-6-luna | 1/2 | 2/2 |
| Antigravity gemini-3.8-flash-low | 2/2 | 2/2 |
| Claude Code sonnet 别名 | 1/1 | 1/1 |

唯一未通过的是 Codex 极简读写用例：计算结果正确，但只返回了 JSON，没有真正写文件。保留失败记录，不能用最终答复代替落盘。正式任务的独立验收器会拦截这种缺失产物。

读取任务的工具定义由 3343 字符降至 357；读写任务由 3790 降至 804。输入负担确实下降，但没有证明质量同步提升。耗时存在明显波动，不用单次耗时推断工具数量的因果影响。

初轮试验的读取用例没有明确字段名，且错误拦截了正常列目录操作，不用于比较成功率；原始记录保留为 `module-load-benchmark-20261025.json`。修正后重新运行并独立核对文件，最终证据为：

- `module-load-benchmark-final-20261025.json`：Codex/Antigravity 8 个有效对照。
- `module-load-claude-20261025.json`：额度恢复后的 Claude 两个读写对照。
- `module-load-audit-summary-20261025.json`：汇总与实际工具数量。
- `module-load-regressions.xml`：相关回归 51 项通过。

这些文件位于工作目录旁 `audit-20261024`，不随源码分发。本报告完成于 10 月 26 日；原对照文件保留执行时的 10 月 25 日日期，未重命名成新的实验。

## 仍需验证

- 大量真实功能 API/外部 MCP 接入后的定义预算与按需发现。
- 多模块并发的延迟、超时、GPU/内存压力和长期稳定性。
- 大任务、多轮切换、不同角色/人设下的重复测量。

本轮不引入未经验证的关键词筛选器来强行隐藏工具，以免切掉文件探索或交付任务所需能力。
