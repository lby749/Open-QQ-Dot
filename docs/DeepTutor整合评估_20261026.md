# DeepTutor 整合评估

核查日期：2026-10-26。按 HKUDS 官方项目评估：<https://github.com/HKUDS/DeepTutor>。
本次核查的 main 提交为 `a31d82624c27d75f4e771d4fcb78dce16470b383`。

## 结论

可以整合，建议作为按需使用的学习与研究专用智能体。保留 Open QQ Dot 的桌面主页、QQ 消息入口、任务持久化、权限、预算和验收体系。此次完成的是文档与源码接口核查，未安装 DeepTutor、未修改运行配置，尚未完成端到端兼容测试。

## 适合引入的能力

- 资料知识库与有依据的问答：把用户指定教材、PDF、笔记接入学习任务。
- 学习路径与评估：按目标组织学习内容，生成练习并跟踪掌握情况。
- 深度解题、资料研读、协作写作与研究辅助：输出解释、笔记及可交付文件。

它不能直接证明本项目的长期无人值守执行、跨账号隔离或浏览器自动化已完成；这些仍需各自实现和验收。

## 已核实的接入接口

- Python SDK：`DeepTutorApp.start_turn`、`stream_turn`、`cancel_turn`、`submit_user_reply`，源码 facade 中存在对应方法。
- 服务方式：`deeptutor serve`；统一 `/ws` 支持任务事件、取消、用户补充和按序号重放。资料、会话、笔记等有 HTTP 接口。
- CLI：`deeptutor run --format json` 输出逐行 JSON 事件。但文档说明无界面 CLI 会以空回复自动回应 `ask_user`，不适合作为需要用户补充信息的默认交互方式。
- 旧 `/api/v1/chat` 和 `/api/v1/ws` 已移除，不能照早期第三方教程实现。

推荐以独立环境和本地服务接入，先使用一个资料研读任务打通上传、执行、进度、补充问题、取消和结果验收。无需先嵌入整套网页。

## 与当前源码的衔接

`agent_tool_adapters.py` 已有外部智能体注册、发现与执行结构，可以复用其展示方式和配置原则。`task_manager.py` 的 `_execute_external_agent` 当前限制在代码和文件任务，不能直接把 DeepTutor 名称加入列表后用于学习任务。需要增加对应的能力路由及执行适配，并继续经过任务权限和验收。

建议由现有任务中心保存本地任务与 DeepTutor 会话、执行 ID 的对应关系。连接中断时先查询原任务，避免重新发送同一提示词；已有序号只拉取后续事件。学习计划作为长期目标的阶段，具体学习回合由 DeepTutor 执行。

桌面控制台直接展示启停、资料、学习目标、进度、暂停与结果。QQ 中识别到学习任务后走相同任务体系，最终按好友人设与回复方式汇报；调试事件、JSON 和执行 ID 留在任务详情。

## 需要处理的边界

1. **单一消息入口**：不同时启用 DeepTutor 对同一 QQ 账号的自动回复通道，避免双重接收、重复回复。
2. **身份与记忆隔离**：明确映射账号、好友、项目与学习会话；不直接合并双方记忆库和人设。
3. **模型登录**：源码有 OpenAI Codex OAuth provider，但其使用 DeepTutor 自己的认证服务。这不等于已经支持复用本项目的登录状态，也不能据此保证 Claude Code 桌面登录直接通用；需分别实测。
4. **依赖隔离**：完整 Python 安装包含检索、模型和服务依赖，建议独立虚拟环境。现有向量模型能否复用，要确认接口、向量维度与索引配置，不能直接共享不兼容的索引文件。
5. **控制提示词体积**：普通聊天仅提供简短的学习能力入口，需要时再传相关资料与任务上下文，不把全部工具和记忆注入每轮聊天。
6. **结果验收**：生成成功不等于内容正确。核查引用对应原文、文件可打开、学习计划可编辑，取消后不继续产出或发送。
7. **分发**：上游为 Apache-2.0；若复制源码或随安装包分发，应保留相关许可证、通知并核查所用依赖许可。

## 接入后的首轮验收

- 同一份测试 PDF：上传、索引、带来源问答、练习、学习计划、笔记交付。
- 暂停、取消、重连、重复提交：不得造成重复模型请求或重复 QQ 汇报。
- 两个测试身份分别上传资料：不能读取对方材料、会话或记忆。
- 桌面操作与手机窄屏操作：可直接管理任务，无须跳转外部工作台。
- 普通 QQ 闲聊：不启动学习运行时、不额外注入全部学习工具。
- 模型认证、向量服务、实际费用与进程停止：独立记录真实结果。
