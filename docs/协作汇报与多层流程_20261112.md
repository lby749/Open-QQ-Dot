# 协作汇报与多层流程（BETA，2026-11-12）

以「最终发布」目录的当前源码为准。本轮未调用 Claude，未注销、切换或重启已登录的 QQ 运行时。好友人设、模型连接配置与加密机器人密钥逐项比较哈希，保持不变。

## 本轮修改

- 节点新增汇报通道：自动选择、群内汇报、私聊主账号、智能体邮箱。主智能体只能从该节点已授权、已接通的通道中选择，固定选择不能被模型覆盖。
- 私聊接入复用既有官方机器人的唯一网关连接。主 QQ 向自己的机器人发起随机码确认，官方网关回复，再由原生 QQ 核对机器人身份、主账号与确认码；不猜测 OpenID，不要求逐个扫码。
- 群回复与私聊回复的授权分别保存。私聊授权过期时，主账号自动请求机器人汇报一次；重复事件不重置回复序号，发送结果不确定时不自动改通道或重发。
- 邮箱汇报使用已有 AgentMailbox，持久保存发件人、上级收件人、消息内容与收取状态。它的消息编号不会被当成 QQ 发送回执。
- 多层流程保存实际分派事件，包含上级、下级、具体任务、模型与通道。运行树将下级调用挂到实际分派下面，区分配置、模型返回、消息送达与产物验收。
- 运行视图合并同一成员的群身份与邮箱身份；已经由 QQ 任务记录展示的同一封邮件不重复计算，独立邮箱会话仍保留。旧版只有群连接的数据库不能因此获得私聊权限。

## 已完成的真实验证

| 场景 | 实际结果 |
|---|---|
| 手动指定私聊＋邮箱 | Luna 规划、两名成员执行、主持人汇总，共 4 次真实调用及返回；机器人私聊正文与发件人匹配，另一名成员的邮箱内容与已收取状态匹配；群内分工、汇总均回读通过 |
| 自动选择群聊＋私聊 | 节点设为自动，主智能体在分工 JSON 中选择通道；共 4 次真实调用及返回；两只机器人的实际群消息/私聊与发送回执分别核对通过 |
| 私聊授权自然过期后恢复 | 没有手动刷新授权或修改过期时间。主账号自动发起一次汇报请求，再由机器人私聊答复；3 次真实调用及返回，主请求回执、机器人正文及群内总结核对通过 |
| 多层分支＋三只官方机器人 | 统筹分派两支任务，检查员再分派给下属并汇总，最后由统筹总结；6 次真实调用及返回、3 份机器人群内结果、2 次分工与最终总结均匹配实际 QQ 历史；下属调用在运行树中确实挂到上级分派下面 |
| 原生桌面窗口 | 实际打开协作流程、选择节点、展开四种通道、保存自动选项并回读文件，再恢复原群内选项；页面切换没有空白。重载后重复身份由 5 项恢复为 3 名真实成员；多层测试历史另保留实际参与的下属身份 |

四轮共 **17 次真实 Luna 调用**，没有使用模型替身。两只机器人的私聊接入、三只机器人的多层群内协作已经实测；不是五只机器人全部私聊、所有模型或任意拓扑组合的证明。真实消息只发到原先授权的主账号、机器人与测试群。多层场景完成后移除了本轮临时节点并恢复原分工与群绑定，原始执行记录保留。
