# 桌面统一接入与聊天任务分流（2026-10-25）

## 现在从哪里操作

启动后进入智能体控制台。侧栏“智能体与工具”统一管理 Codex、Claude Code、Antigravity、DeepSeek Harness、自定义 API、OpenCode、Cursor、Qwen Code、Kimi Code 和自定义 ACP 智能体。

它们共用主智能体选择、协作勾选、交接顺序、控制台选择器、模型分发和任务执行路径。协作网络的“配置与管理智能体”直接切换到桌面配置页，不再要求打开网页。旧的外部工具只读安装表已移除。

程序路径、启动参数、本机服务地址、ACP 协议版本可以直接配置、保存、重新加载及检测。新增接入沿用各工具自身的模型与登录设置，不展示虚构的模型列表或登录成功状态。

MCP 在同一页管理，作为工具服务接入 Codex 和 Claude Code，不冒充独立语言模型。通用外部进程的完整电脑访问、命令执行与只读限制继续生效；保存或勾选智能体不会自动扩大权限。

接入沿用现有协议实现，参考官方说明：[OpenCode 服务接口](https://docs.opencode.ai/docs/server/)、[Cursor 无界面模式](https://docs.cursor.com/en/cli/headless)、[Qwen Code 无界面模式](https://qwenlm.github.io/qwen-code-docs/en/users/features/headless/)、[Kimi Code ACP](https://www.kimi.com/code/docs/en/kimi-code-cli/guides/ides)。

## 聊天和任务如何区分

| 入口 | 行为 | 结果去向 |
| --- | --- | --- |
| 工作台，执行任务 | 默认创建持久化任务，进入现有任务系统执行与验收 | 任务中心、工作台会话、桌面通知；默认不发到 QQ |
| 工作台，直接对话 | 显式切换后直接生成回复 | 当前工作台会话 |
| 工作台，QQ 消息流 | 将操作者输入的原文发给当前好友 | QQ；不会误当作工作台任务 |
| QQ 日常来信 | 沿用现有聊天回复流程 | 按当前好友的人设与回复方式聊天 |
| QQ 明确委托 | 如“任务：…”、“帮我修复项目…”、“帮我打开网址并截图”，创建任务 | 执行过程留在控制台；接单、进展及结果通过 QQ 汇报 |

仅提到“网页、代码、论文、任务”不等于下达任务。讨论、假设、引用别人说的话不会仅因这些关键词就启动后台工作。模糊来信继续交给正常聊天流程理解或询问，不扩大成自主执行授权。

工作台会话分别记住“执行任务／直接对话”的选择；新会话默认执行任务。手机工作台也提供对应选择。工作台项目通过已登记的当前好友工作区解析，不从任务文本接受任意执行目录。

工作台任务的工具审批也留在本地。QQ 任务仍遵守已有操作权限和审批机制。任务接单回复失败或 QQ 重试时，相同输入事件的幂等键不会重新创建已结束的任务。

## QQ 口吻从哪里来

没有另设一套固定口语人格。QQ 任务接单、状态查询、任务控制结果和完成通知，复用普通聊天的 `conversation_context`、角色模板范例、相关记忆、称呼、情绪设置及 `tidy_bubbles` 气泡处理。

配置入口仍是“设置与工具 → 人设与指令 → 人设与回复风格”及角色模板选择。这里配置正式、冷静、亲近或其他说话方式，就按该好友自己的配置表达；不会统一套成朋友闲聊口吻。

任务进展以真实状态和事项作为事实输入，不把原始 JSON、堆栈、内部编号或本机路径发到 QQ。失败、暂停、待验收不改称成功。完整技术结果保存在控制台。

通知表达在后台准备，避免阻塞 QQ 聊天循环；模型暂时不能整理时保留待发送状态，不回退发送原始日志。生成结果、已发送气泡和不确定回执状态持久化，避免重启或网络异常后重复发送。
