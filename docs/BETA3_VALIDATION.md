# Open QQ Dot BETA.3 发布验证报告

日期：2026-11-12。以“最终发布”当前源码为准。范围是 Windows 一键配置启动器、协作汇报及本轮可靠性修正。自建 QQ 群已按用户要求暂缓，不宣称它已修复。

## 实际修改

- 用量页不再解析其他好友或项目的完整 Codex 会话。其他近期会话仅限读取末尾 128 KiB 的账号额度事件；当前好友自己的完整统计仍保持原作用域。
- 修复删除/切换好友后的延迟配置读取，以及关闭窗口后迟到的状态回调；清除导航清单中的重复别名。
- 经验审计编号不再依赖系统时间。虚拟机连续写入曾实际发生主键冲突；固定时钟测试先复现失败，再改为独立 UUID，验证完整状态写入。
- 修复主题更新时控件销毁引起的弱字典迭代异常。先获取稳定、有效的控件快照，保持原界面风格；不是吞掉错误或跳过界面检查。
- 修复可选用量插件缺失时的测试资源清理。准备阶段跳过的测试也会关闭数据库并删除临时目录；实测跳过后仍打开的连接由 7 个降为 0，随后重新运行完整套件。
- 本地向量环境通过 Windows 运行依赖包补齐 DLL，并在当前虚拟环境的 Torch 目录中部署缺少的文件及许可证。不安装系统级运行库，不覆盖已有 DLL。实际导入失败会保持不可用；不会把成功下载后的导入问题当成换源重装问题。
- 发布版本及两个 EXE 的版本资源更新为 1.0.0-beta.3。
- 桌面依赖冻结为 PySide/Qt 6.11.2。空环境原先自动取得 6.12.0，测试断言结束后在其 DLL 中访问冲突；失败进程没有被当成通过。改用本机已验收基线，再重新首装和完整回归。
- 轮次截止时间使用整数纳秒。原先浮点加减在边界返回了 `60.00000000000023`，超过 60 秒断言；先固定时钟稳定复现，再修计时表示，原断言加强为精确值，并验证短嵌套结束后恢复外层预算，没有增加容差。
- 研究假设、决策和分支不再用截断的毫秒值作主键。重复时钟和截断值回绕都会碰撞，已用固定时钟先复现三个数据库主键错误；现用独立 UUID，不迁移旧记录、不放宽权限。
- 任务经验也不再使用时间与短内容摘要组合成主键。同任务、同问题的不同动作曾被静默覆盖，固定时钟实测 3 条仅剩 1 个编号；改用独立 UUID 后保留全部记录及审计。没有回填或重建历史库，也未把普通聊天加入经验库。
- 发布前再次清理旧文档和示例命令中的真实 QQ 号码与消息回执，原始私有证据留在构建目录；未修改实际好友和密钥文件。

## 空环境首装与修复

新建独立 Windows 环境后先确认：没有 Python 命令、没有应用目录，系统目录中也没有 `msvcp140.dll`。仅映射程序包、测试脚本及先前验证的公开依赖下载缓存；缓存没有预装到环境中，未强制重新下载已经存在的包。

实际执行最终 EXE 的默认安装选项，保留 CPU 向量环境选项，然后核对 SQLite、SSL、Qt、Torch 与 transformers 的真实导入。随后再次执行默认覆盖修复，合成数据哨兵保持一致。薄启动 EXE 的准备检查通过，最终安装目录的实际窗口标题为 `Open QQ Dot v1.0.0-beta.3`。

最终已测 Python 3.12.13、Qt 6.11.2、Torch 2.15.0+cpu、transformers 4.57.6；Windows 运行依赖 msvc-runtime 14.51.36231。全量测试进程正常退出，退出码为 0。系统运行库缺失时，实际 DLL 加载路径位于应用虚拟环境。模型权重、QQ 登录态和私人账号没有预装或复制进沙箱。

这是本机 Windows Sandbox，不是远程云主机。窗口标题和组件检查不等于每个隐藏页面的目视验收。本轮用户按 Esc 停止了原生电脑操作，之后没有重启宿主正在使用的旧窗口；当前宿主窗口不能据此宣称已加载 BETA.3。

## 保留的失败和限制

- 早期主机全量出现过 4 项失败；最终修正后的结果另行记录，没有把旧结果改成零失败。
- 早期沙箱全量出现 1 项失败、6 项界面初始化错误。根因分别是测试把健康系统 Python 放进了临时目录，以及控件销毁期间的主题登记集合变化。安全过滤未放宽，主题错误先稳定复现再修复。
- 微软系统安装器下载/等待曾失败；后续空环境又暴露短链接和直链连接超时。最终方案已移除这一系统安装器路径，使用应用内运行依赖；原失败记录保留。
- 测试工具从 PyPI 直连下载超时，改用与程序一致的镜像继续。默认安装和数据保留的原始成功证据保持不变。
- 最终环境的测试工具镜像也曾连接超时，随后使用已缓存的公开测试依赖离线安装继续；没有重装应用，也没有重复下载。该准备失败的报告单独保留。
- 首次最终沙箱全量虽无失败，但出现 7 条临时数据库删除警告。定位为准备阶段跳过时未执行原 tearDown，改用立即登记的清理函数；保留旧日志，并对最终源码再次跑完整回归。
- 随后的 Qt 6.12.0 全量虽有 2468 项通过、25 项跳过且无警告，但测试进程退出码为 -1073741819。Windows 事件将故障模块定位为 `pyside6.abi3.dll`；该轮整体仍记为失败。当前发布冻结到已验证的 6.11.2，而不是关闭退出码检查或强制退出；这不等于修复或完全查明了 Qt 上游的原生内存问题。
- 第一轮 Qt 6.11.2 全量正常退出为测试失败码 1，2467 项通过、1 项计时边界失败、25 项跳过。浮点预算错误已按上文修复；这轮原始结果没有覆盖，最终快照重新走首装、修复和全量。
- 下一轮全量再次正常退出为测试失败码 1，2467 项通过、25 项跳过，唯一失败发生在研究假设写入：`research_hypotheses.hypothesis_id` 主键碰撞。越权更新尚未执行；单独复核曾通过，但不能抹掉全量失败。沿同类编号排查后，另复现决策、分支碰撞和经验覆盖，一并修正并重新完整验证。
- 真实模型/QQ 证据来自有限授权场景；Mac、Linux、APK、实体手机、所有隐藏界面、全模型组合、长时间无人值守及自动建群没有因此获得新的通过结论。本轮没有发布 GitHub，也没有重新打包 APK。
- 本轮未重新评测开放域检索质量和全部性能指标。套件耗时不能充当严格的优化前后性能比较，测试通过率也不换算为整体工程评分。

最终跳过原因按项记录在随包 `validation-results.json`，包括缺少可选工具/模型和平台不适用；没有把跳过项计为通过。具体功能边界另见 [已知问题](KNOWN_ISSUES.md)。
