# 审计问题深度修复：阶段报告（2026-10-26）

本轮以用户最新源码为基线，保留现有界面、账号数据、公共学习工具和任务系统。根据随后“先不急着做全量测试”的指示，完成根因修复与必要的小范围验证，暂缓全量、批量模型端到端和最终评分。这里不是开源验收完成声明。

## 已定位与修改的根因

### 1. 源快照变化中断主动轮次

用户截图的原始事件可在私有运行日志中找到。源码有两个需要处理的并发点：

- 较早聊天摘要的模型调用期间，新消息、记忆整理或资料变化会使源快照失效。原实现只在生成前捕获异常，提交摘要时的校验异常会直接上抛到主动轮次。现在仍拒绝旧结果和旧游标，但保留原摘要、设置短暂退避，当前轮次不因这项可选摘要的失效而中断，也不重复调用模型。
- 近期对话与核心记忆的短读之前依靠多次独立快照，写线程可在这些读取之间改动数据。`conversation_context` 现在只在这段本地读取期间持有好友源锁，形成一致的读视图。模型调用、长检索与分析不持锁；读取后仍检查源引用与快照。并发测试证明写方会在短读之后提交，也证明同一读过程内实际发生的数据变化依旧被拒绝。

底层区分“旧记录缺少校验信息”和“源资料在处理中变化”，错误提示改为中文。没有删除快照检查、放宽旧记录信任或自动接纳失效结果。截图事件只有一行异常消息，没有调用栈，因此不能声称已凭日志确定当时唯一的调用点；本轮修复的是已复现的上述两条路径，运行进程需重启后才能验证实际事件是否再现。

### 2. 经验检索把模型分数当成单一否决条件

实际模型探查显示：正确的 npm 代理经验重排分数为约 0.0456，低于原来的 0.1 固定线；“rate limit”与“429 Too Many Requests”缺少共同的诊断表示，即使真实相关也被漏掉。双向重排也不能修复查重语义：两个不同页面故障的相关性分数依然接近 0.99。

修复采用多信号判断：

- 在共用分词入口归一化明确的协议、错误码与诊断名称，保留原文，不改写原始记录。
- 明确诊断名称相同，或技术标识、词面证据、向量支持与最低重排证据同时成立时，保留该候选。普通低分、无证据的条目仍被过滤。
- 查重在相关性判断前检查任务目标、日期、动作极性，以及任务类别和项目范围。相同幂等键若对应不同内容或项目，在数据库事务中直接拒绝复用；不是跳过错误后再新建一个任务。

这组规则由本轮故障样本参与了定位，原留出集现在应视为开发回归集，不能再当作从未见过的独立验证集。规则的泛化仍需另一套新样本评估。

### 3. 缓存与多模型选择的边界不完整

- 查询与重排缓存增加好友/运行目录作用域、当前本地模型开关和凭据版本；缓存命中不能绕过模型停用或凭据变化。API 向量空间签名包含凭据版本摘要，不把凭据原文写进缓存键。
- 缓存中的查询向量采用不可变存储，调用方拿到副本，修改返回值不会污染下一次请求。
- 向量批次先整体验证条数、维度和有限数值，再写入缓存；重排不能把短结果默默补成零分。
- 损坏的磁盘向量会重新计算，同批重复文本只计算一次；文档缓存有实际行数上限。
- 自动选择的建库向量模型不再随瞬时空闲显存切换，避免同一集合的查询与文档落入不同空间。重排模型仍可按资源选择。只有英文能力的模型不再被自动拿来处理中文；同时支持中英文的模型仍可以服务混合语言。

### 4. 统一检索需要走到生产路径

- 好友记忆查询、话题查询和公共学习资料查询复用共用词面入口；资料查询保持轻量词面模式，不在工具子进程额外装载一套 GPU 模型。
- 经验、工具、历史、跨智能体记忆继续复用统一的向量/重排核心，业务类型保留自己的可见性与取舍规则。
- 历史参考接入实际统一编排、原生外部智能体及 Codex App Server 任务入口。检索词使用具体任务描述，而不是整段通用安全提示；最多三条，带来源并标明是不可信参考，沿用现有会话续接。
- 任务完成时保存项目来源；工具推荐排除未安装、停用及实际权限不允许的条目。跨属主共享经验必须经过有效验证，不能仅凭“共享”标记传播未核验建议。

这不是把不同数据库或隐私范围合并成一个库；各业务的生命周期、权限和验证状态仍然分别保留。

### 5. 发布包过滤范围不足

增加认证状态、证书/私钥、浏览器会话、SQLite/WAL/SHM、源校验 nonce、常见包管理器凭据等文件过滤；规则不依赖大小写。打包不进入符号链接或 Windows 目录联接。前端与脚本源码也参与凭据检查，并补充常见厂商令牌及加密私钥模式，命中时只显示文件位置，不打印密钥。

## 验证与保留的失败

最终相关回归 **68 项通过**，包含 19 个本轮缺陷复现检查，以及已有的源语境、会话去重、模型选择、检索和打包检查。没有运行全量。测试替身用于逻辑/权限验证，GPU 子集单独采用真实模型。

中间曾有两项失败，原始 XML 保留：

1. 自动语言选择修复最初排除了同时声明中英文的模型，导致另一向量预设的兼容测试失败。已修正语言覆盖判断，随后通过。
2. 多个测试文件放在同一进程后，已有测试加载的重排模型使“未加载大模型时应该选小模型”的测试前提不成立。测试现在明确设置未加载状态；生产代码仍优先复用已加载且可用的模型。

证据位于 `audit-20261026-deepfix`：

- `bench/audit-before-heldout-real.json`：修改前的实际模型结果。
- `bench/audit-after-targeted-heldout-real.json`：经验与查重子集复测。

- `focused-validation-final.xml`：最终 68 项相关回归。
