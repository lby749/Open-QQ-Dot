# Open QQ Dot · BETA 测试版

**把 QQ 中的需求变成可以规划、执行和追踪的任务。**

Open QQ Dot 是运行在自己电脑上的中文自主智能助手。你可以通过 QQ 交办工作，在桌面查看计划、工具调用和执行结果，让多个模型分工协作，也可以通过配对的蓝色安卓客户端查看任务和参与协作。它还提供好友独立的人设与记忆、可复用工作流，以及分阶段的长期任务和研究流程。

**当前版本：`1.0.0-beta.3`。** 这是测试版，仍有未完成和未验证的功能。测试替身、真实组件、真实模型、QQ、实体手机与云端安装的证据分别记录；某项测试通过不代表所有模型、所有功能和所有平台均已验收。

## 主要功能与优势

| 主要功能 | 能帮你解决什么问题 |
|---|---|
| 自主规划与执行 | 把目标拆成步骤，调用获准的浏览器、文件和终端工具；查看产物与验收记录，知道任务进行到哪里 |
| 可编辑的多智能体协作 | 用入口和分支节点组织分工，配置成员、模型与思考强度；通过群聊、私聊或内部邮箱汇报，并查看实际交接 |
| 长期任务与阶段式研究 | 设置阶段、预算、检查点和停止条件，保留进度与实验记录；遇到不确定的外部执行结果先核查，避免重复操作 |
| 可学习工作流与任务胶囊 | 将已验收任务和你的纠正整理为可编辑流程，以后复用、修改和导入；不把普通聊天全部当作任务经验 |
| 按好友管理聊天与权限 | 每位好友分别配置人设、回复偏好、记忆与工具授权；共享模型权重，隔离任务、向量集合和检索缓存 |
| 模型、MCP 与多端入口 | 在统一设置中接入 CLI、API 和外部智能体，按需提供工具与上下文；QQ 交办、桌面管理、手机查看与协作 |

本地部署让你保留自己的资料与运行目录；使用云端模型时，回答或执行所需的内容仍会按设置发送给所选服务。电脑需要保持运行，手机端依赖电脑服务。跨多日无人值守、完整科研闭环和任意模型组合仍属于 BETA 验证范围。

完整入口、用途和成熟度见 [功能目录](docs/FEATURES.md)。重复入口会指向同一套任务、工作流或模型配置，并不是额外的执行引擎。

近期个人智能体的源码架构、已采用机制和仍未完成部分见 [架构核查](docs/近期个人智能体架构核查_20261111.md)。

## 下载与安装

发布资产按用途分开，具体文件名和哈希以对应版本的清单为准：

- **Windows 一键配置启动器（EXE）**：用于新装或修复，在应用目录准备私有 Python 与依赖；不要求预先安装 Python。BETA.3 已在初始无 Python 的独立 Windows Sandbox 实测首装、修复和启动；这不是远程云主机证明。
- **绿色包（ZIP）**：包含程序源码和入口，适合查看或迁移；不是包含全部模型、运行时和登录态的离线整合包。
- **完整源码（ZIP）**：包含测试、工具和开发文档，供审查与自行构建。
- **安卓应用（APK）**：保留原蓝色配套界面，正式安卓源码位于 `android/`；废案 `mobile/` 不随发行包提供。当前使用调试签名，实体手机完整验收尚未完成。

模型、账号和外部服务不随安装包提供。模型权重按需下载并可共用；好友记忆、向量集合、经验和检索缓存仍按身份与权限隔离。

「设置与工具 → 版本与更新」提供自动检查、中文更新说明和新版下载入口；自动检查每天最多一次，同一版本只提示一次，可关闭。正式发布时绑定本项目的实际公开仓库；绑定前会明确显示尚未配置来源，不误报“已是最新版”。

### Windows

1. 将一键配置启动器放在可写目录运行，选择独立的应用目录。
2. 等待 Python 和基础依赖准备完成，再打开桌面控制台。安装器优先复用已有可用资源，不下载全部向量、语音或生成模型。
3. 在模型与工具设置中配置自己有权限使用的 CLI 或 API，设置工作目录和工具权限。
4. 打开「QQ 连接」，选择官方机器人并完成所需配置。安装成功不等于 QQ 已连接或模型已授权。

更新、修复前请保留原目录备份。好友、聊天、登录态和本机配置不应被发布包覆盖；不要把私人运行目录整体上传到仓库。启动失败时保留错误和安装日志，不能用空白窗口或后台进程存在作为成功依据。

### macOS 与 Linux

提供 `sh start.sh` 和 macOS 的 `Open QQ Dot.command` 源码入口，平台状态见 [跨平台启动说明](docs/macOS与Linux源码启动_20261026.md)。原生应用包、系统签名、托盘、图形桌面和平台特定 QQ 连接须在目标机器单独验证。Linux 容器中的组件测试不代表真实桌面验收。

## QQ 连接

首次默认使用 **官方 QQ 机器人**。准备自己的机器人 AppID 与密钥，并按平台允许的场景配置；不同机器人身份、群组和发送者分别绑定权限。五个官方账号已通过真实鉴权、网关连接和既有群接入；有限真实 Luna 场景验证了私聊、群聊、内部邮箱、自动汇报选择及多层协作。范围见[本版发行说明](docs/RELEASE_BETA3.md)，不代表任意模型和群均已验收。自动建群已暂缓。

原有接口与界面保留为独立的 **个人 QQ 账号直连（NAPCAT）** 入口。使用自己的 QQ 账号。有风险。

两种连接方式分开配置，切换界面不会自动登录或发送消息。已有个人账号登录数据应保留；发布包不包含开发者的账号、密钥、QQ 运行时和登录状态。项目与腾讯没有隶属关系。

## 聊天与任务怎样区分

工作台输入默认按工作任务处理。QQ 中既可以聊天，也可以提出任务；任务状态、调试记录和验收 JSON 保存在任务界面，QQ 汇报应遵循该好友的人设与回复方式，避免把内部协议和完整诊断堆给对方。

任务产物需要独立核对。文件任务检查内容和测试命令，浏览器任务核对实际页面与产物；模型自称完成不能作为完成证据。对于可能已执行的外部操作，保留收据等待核查，不能在超时后自动重复发送。

## 模型、工具与检索

支持单智能体运行或由一个主智能体分工。不同模型、CLI、API 的能力、配额和认证方式各不相同，只有已完成的具体组合可以称为已验收；本项目不会把桌面端登录状态自动等同为所有 CLI 均已登录。

通过 MCP 按需取得当前身份、配置、能力与工具，不把全部文档、历史记录和工具 schema 每次都塞入提示词。运行接入见 [智能体接入说明](docs/AGENT_INTEGRATION.md)；参与开发的智能体请读 [AGENTS.md](AGENTS.md)。

统一检索复用向量、关键词、融合和重排能力，但权限过滤始终先于结果交付。现有对比包含单向量、关键词、融合、重排和组合模式；已知条目找回率不是人工语义评分，也不是模型完成任务的成功率。手动配置的 1080 种组合各有独立生成的24条消息，转换为每组12个回复示例，共12,960个；性格、关系、双方性别和主动频率均精确对应。示例只参考表达，不作为真实经历或任务经验。占用档复用这套文本，向量缓存按实际模型和好友隔离，不复制模型权重；手动指定的检索模型优先于占用档。规则和去重检查通过不代表全部对话已完成人工审查。

## 开发与验证

在隔离开发环境中安装基础界面依赖，再单独安装 Fluent 组件，避免引入未使用的 WebEngine：

```text
python -m pip install -r requirements-ui-core.txt pytest
python -m pip install --no-deps -r requirements-ui-qfluent.txt
python -X utf8 -m pytest -q tests
python -X utf8 tools/package_release.py --check-only
```

测试只用临时目录和合成身份。涉及真实模型、账号、QQ 或实体设备的项目单独执行，使用有限调用与时间预算；没有凭据或设备时写明未验证。完整回归须记录失败、跳过、耗时及运行平台，不能只报告选中的通过项。

源码打包与核对：

```text
python -X utf8 tools/package_release.py --root . --output OpenQQDot-source.zip
python -X utf8 tools/verify_release_archive.py --source OpenQQDot-source.zip
```

打包扫描只能检查已支持的模式，不是完整安全审计。运行数据、配置密钥、好友资料、数据库、日志、认证文件、本机环境和模型权重不能进入公开仓库。
